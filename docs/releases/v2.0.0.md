# dcARCA v2.0.0

Release mayor de hardening de Core y consolidación del servidor MCP como superficie remota soportada.

## Highlights

- MCP autenticado con OAuth/JWT y scopes separados para lectura y emisión.
- Emisión de alto nivel con numeración server-side y serialización por secuencia fiscal.
- Reconciliación de timeouts/resultados inciertos antes de repetir una emisión.
- Modelo fiscal WSFE generalizado: múltiples alícuotas, exentos, no gravados, tributos, moneda y cotización.
- Cache WSAA desacoplado mediante `IWsaaTokenStore`, memoria por defecto y filesystem explícito/endurecido.
- Health/readiness y configuración segura por ambiente.
- Retiro de la API REST no autenticada; MCP queda como única superficie remota soportada.

## Breaking changes

### Cache WSAA

Antes se escribía automáticamente un JSON local con `token` y `sign`. Desde v2.0.0 el default es `MemoryWsaaTokenStore.Shared`.

Para persistencia explícita:

```csharp
var tokenStore = new FileSystemWsaaTokenStore();
var auth = new dcArcaAuthService(
    config.WsaaUrl,
    config.CertificatePath,
    config.CertificatePassword,
    config.Cuit,
    tokenStore: tokenStore);
```

Un host que requiera cifrado, KMS/Vault o coordinación distribuida puede implementar `IWsaaTokenStore`.

### Modelo fiscal

`ImporteIva > 0` requiere `AlicuotaIva` o detalle `Iva`. Ya no se infiere automáticamente IVA 21% a partir de los importes.

El request admite además `ImporteNoGravado`, `ImporteExento`, `Tributos`, `MonedaId` y `MonedaCotizacion`.

### REST/CLI

`dcArca.Service` fue retirado. Sus comandos locales permanecen en `dcArca.Cli`.

Para acceso remoto debe utilizarse `dcArca.McpServer` con un Authorization Server OIDC/JWT externo.

### Scopes MCP

Los scopes son independientes:

- `arca:consultar`: tools de lectura.
- `arca:facturar`: tools de emisión.

Un cliente que necesite ambas capacidades debe solicitar ambos.

## Emisión MCP

El flujo recomendado es `emitir_comprobante`/la operación avanzada equivalente documentada en `docs/MCP_SERVER.md`, donde el servidor consulta el último comprobante y asigna el siguiente número dentro de un lock por `(CUIT, PuntoVenta, TipoComprobante)`.

El lock es in-process. Para múltiples réplicas que compartan un punto de venta se requiere coordinación distribuida o un punto de venta dedicado.

## Resultado incierto

Ante un error de transporte potencialmente posterior al envío de `FECAESolicitar`, dcARCA consulta `FECompConsultar` antes de decidir si la operación fue autorizada. No se realiza un reintento ciego de la emisión.

## Seguridad y operación

- No existe deploy productivo desde este repositorio público.
- Docker/compose son ejemplos genéricos y no describen infraestructura privada.
- Certificados, PFX, passwords, client secrets y tokens no deben incorporarse al repositorio.
- TLS/OIDC metadata HTTPS son obligatorios fuera de Development.
- `/health/live` y `/health/ready` no exponen CUIT, certificados ni credenciales.

## Baseline

El tag `v2.0.0` debe apuntar al commit de `main` resultante del PR de release. Ese tag, y no un commit intermedio, es el baseline aprobado para derivar el futuro repositorio privado de Cadencia.
